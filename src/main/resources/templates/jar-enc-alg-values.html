The list, and the key it says nothing about

request_object_encryption_alg_values_supported tells a client which key-management algorithms this server will unwrap a request object with. It does not tell it which key to wrap to — that is in /oauth2/jwks, where this server publishes three, two of them RSA. A client needs a value from the list, the algorithm it registered, and the right key; the page sends five objects that each have two of the three.

Reading this

Rows one and two differ only in the key. Same algorithm, same client, same registration — one wrapped to the key marked enc and one to an RSA key marked sig. The second is refused with "could not be decrypted", which is true and unhelpful: the server cannot tell a client that picked the wrong key from an attacker that guessed. The algorithm list does not prevent this mistake, and it is not supposed to — use on the published key is what does.

Both RSA keys now say what they are for. RFC 7517 §4.2 makes use optional, and until this page only the encryption key carried it — so a client had to pick the encryption key by the absence of a marking on the others. All three are marked now, which is the difference between selecting a key and guessing one.

The list is the server's, not the client's. Row three sends RSA-OAEP-512 — advertised, and refused, because the client sending it registered RSA-OAEP-256. Row four sends the same algorithm from the client that registered it and is unwrapped. The same pairing as the signing list, one specification over.

Off the list is off the list. The fifth row is RSA1_5, registered by the client that sends it and refused because this server does not advertise unwrapping it. That is the one the page would be incomplete without: it is a real JWA algorithm, it is what that client agreed to, and the list is the thing that says no.

The other half of the pair is separate. This list covers the alg — how the content encryption key travels. The enc list covers what that key then does, and the two are advertised, registered and chosen independently.
