JWT client assertions (private_key_jwt)

RFC 7523. Instead of sending a shared secret on every call, the client signs a short-lived JWT with a private key and sends that. The authorization server holds only the public half, so there is no secret to leak from its database — and none in transit either.

How this client is registered

client_id pkce-assertion-client
Authentication private_key_jwt (RS256, no secret stored)
Grant client_credentials — no user is involved
jwkSetUrl /client-jwks.json The server fetches this when it has an assertion to verify. Rotating the key means publishing a new one; there is nothing to coordinate.
