Logging someone out without their browser

OpenID Connect Back-Channel Logout. Every logout so far on these pages needed the user's browser to go somewhere. This one does not: the authorization server posts a signed logout token straight to each client that has a session for that user, and the client ends it. No redirect, no cookie, nothing for the user to click — which is the only way a logout can reach a client the user is not currently looking at.

Reading this

Spring Authorization Server has no sending half. Nothing in it mentions back-channel logout: no logout token, no backchannel_logout_uri on a registration, nothing sent when a session ends. The tokens on this page are minted and posted by BackChannelLogoutService, with the server's own signing key.

Spring Security has the receiving half, and it is one line. oidcLogout(oidc -> oidc.backChannel(...)) puts the endpoint above in place, validates the token against the issuer's published keys, and ends the matching sessions. The validation is OidcBackChannelLogoutTokenValidator; the five refusals above are its rules, one each.

One of those refusals is a 500, and should not be. OidcBackChannelLogoutTokenValidator means to report a missing events claim as an ordinary validation error — the line right after the check says so. It never gets there: reading the claim goes through LogoutTokenClaimAccessor.getEvents(), which asserts the claim is not null and throws first, and the filter turns that into a 500. The token is refused either way; the client just answers the wrong thing to a request that is merely malformed.

The sid claim was already there. Matching by session needs the ID token to carry one, and Spring Authorization Server issues it already, from its session registry — so the logout tokens here name that same value rather than inventing one. Without a sid a logout token can only name a subject, and the client then ends every session that user has: right for "sign out everywhere", wrong for signing out of one browser.

Neither metadata document advertises back-channel logout, and that is deliberate. backchannel_logout_supported would mean this server sends a logout token whenever a session ends, and it does not — it sends them when this page asks it to. Advertising the flag would describe a server that does not exist, which is the one thing the metadata page is about.

This is the third kind of logout here, and they do different work. Local logout ends the client's session; RP-initiated logout sends the user to the server to end that one; revocation ends the tokens. Back-channel logout is how the other clients find out at all.
