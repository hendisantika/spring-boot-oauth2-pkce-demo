Authorization Code flow with PKCE

This one application plays both roles: it is the authorization server that issues the tokens, and the public client that logs in against it. The client holds no secret, so the authorization code is bound to the caller with a PKCE code challenge instead.

Start the flow

You will be sent to /oauth2/authorize with a code_challenge, asked to sign in, asked to approve the scopes, and redirected back with an authorization code that is only redeemable with the matching code_verifier.

Sign in with PKCE

Or sign in as the confidential client

The same flow, but the client also holds a secret. PKCE still applies — it is not only for public clients. The difference you can see: this one is issued a refresh token, because Spring Authorization Server withholds refresh tokens from clients that authenticate with nothing. That is what the Refresh page exercises.
